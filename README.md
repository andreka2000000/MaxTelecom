# МаксТелеком

Порядок там, где раньше был хаос. MVP диспетчеризации выездных бригад: абонент → диспетчер → исполнитель → отчёт → оценка сотрудника.

## Запуск одной командой

Нужны Git, запущенный Docker Desktop с Linux containers и Docker Compose v2. При первой сборке нужен интернет для образов и Python/npm-пакетов. Рекомендуется 8 ГБ оперативной памяти для Docker; порт 8080 должен быть свободен.

```bash
git clone https://github.com/andreka2000000/MaxTelecom.git
cd MaxTelecom
docker compose -f compose.deploy.yaml up -d --build --wait
```

Откройте **http://localhost:8080**. Node.js, Go, Python и PostgreSQL на компьютере устанавливать не требуется. Первая сборка и подготовка дорожного графа могут занять несколько минут.

Получить локальные демонстрационные аккаунты:

```bash
docker compose -f compose.deploy.yaml exec --user 0 api cat /demo/demo-accounts.json
```

`dispatcher` — диспетчер с управлением; `subscriber` — абонент; `technician` — ST-001; остальные исполнители — `demo.st-002`…`demo.st-040`. Пароли генерируются при первом старте, хранятся в Docker-томе и сохраняются при повторном запуске. Не публикуйте их. Для разных ролей используйте разные профили браузера либо выходите из аккаунта перед сменой роли.

## Демонстрационные данные

| Даты ноября 2026 | Данные |
|---|---|
| 14, 15, 16 | По 400 учебных нарядов и 40 сотрудников; отдельный план каждого дня |
| 17 | Тестовая смена для новых обращений и полного клиентского цикла |

Часовой пояс — Екатеринбург, UTC+5. По умолчанию смены работают в DEMO: время продвигает диспетчер. Исходные синтетические JSON-файлы содержат исходную дату кейса; загрузчик переносит её на демонстрационные даты. Повторный запуск не заменяет существующие смены, обращения и оценки.

## Рабочий цикл

1. Абонент выбирает услугу на главной, входит и отправляет обращение.
2. Диспетчер открывает обращения, согласует адрес и окно визита на 17 ноября. План должен быть построен; в тестовой смене он создаётся автоматически.
3. После одобрения наряд включается в план. Диспетчер может изменить исполнителя с проверкой ограничений.
4. Исполнитель входит своим аккаунтом, выбирает ту же дату и видит адрес, контакт и маршрут. Кнопки: «Выехал», «Прибыл», «Начал работу», «Закончил работу». Завершение требует отчёта.
5. Абонент видит результат и может один раз оценить сотрудника от 1 до 5. Средний балл и число оценок доступны диспетчеру в команде. У сотрудников без отзывов показано «Пока нет оценок».

Если выезд или старт недоступны, проверьте время смены и предыдущие незавершённые задания. Для репетиции полного цикла используйте 17 ноября; массив 400 нарядов нужен для демонстрации планирования. [Подробная инструкция](USER_GUIDE.md).

## Обновление и остановка

```bash
git pull origin main
docker compose -f compose.deploy.yaml up -d --build --wait
# Остановка с сохранением данных
docker compose -f compose.deploy.yaml down
# Диагностика
docker compose -f compose.deploy.yaml ps
docker compose -f compose.deploy.yaml logs --tail 100 api frontend optimizer bootstrap
```

Не используйте `down -v`, если данные нужны: флаг удаляет тома с базой и аккаунтами. Если 8080 занят, задайте `DEMO_PORT` через `.env`, например `DEMO_PORT=8082`, и повторите запуск. Не запускайте одновременно оба Compose-комплекта на одном порту.

Если pip сообщает `ReadTimeoutError` от pypi.org, проверьте интернет Docker/прокси и повторите сборку. В Dockerfile предусмотрены ожидание 300 секунд и 10 повторов. Сообщение «версии не найдены» после сетевого тайм-аута не означает, что зависимость отсутствует.

## Реализовано и ограничения

Сессии и серверные роли, обработка обращений, ручные назначения, карточки сотрудников, DEMO/LIVE-время, подтверждение этапов, дорожные маршруты OSRM, PyVRP с Go fallback, проверка ограничений, событийное перепланирование, уведомления внутри приложения и оценки. Критические изменения сохраняются атомарно; повтор события не создаёт дубль.

GPS, живые пробки, чат и внешние push/SMS/email не реализованы. HTTPS отложен. Отметки прочтения уведомлений хранятся в текущем браузере. Карты и внешний навигатор требуют интернета; дорожный граф включён в сборку. География, сотрудники и нормативы демонстрационные.

## Разработка

Frontend: Next.js / React / TypeScript. Backend: Go / PostgreSQL. Отдельные сервисы оптимизации и дорожной маршрутизации. `compose.yaml` — комплект разработки: интерфейс 8080, API 8081, PostgreSQL 15432. Локальные значения `.env` могут переопределять порты. Основной способ запуска для комиссии — `compose.deploy.yaml` выше.

Проверки: `npm ci && npm run check`; в `backend` — `go test ./...` и `go vet ./...`. Для интеграционных тестов задайте `TEST_DATABASE_URL`; они создают и удаляют только свои PostgreSQL-схемы. Секреты, локальная `.env` и `work/` не входят в Git. Шрифты Manrope и Russo One включены локально с лицензиями OFL; атрибуция OSM сохранена в интерфейсе.
