## 1. Как открыть проект

Каталог проекта: `C:\Users\Dmitriy\WebstormProjects\Hakaton(Smart-dispatcher)`.

Для обычного запуска откройте терминал в этом каталоге:

```powershell
docker compose --profile routing up -d --wait
```

Откройте **http://127.0.0.1:3001/login**. Если обновляли исходный код, сначала выполните `docker compose build api frontend`, затем обычный запуск. Не выполняйте повторный импорт с `--replace` перед защитой: он предназначен для явной замены учебной БД.

Логины и локальные демонстрационные пароли: `work/demo-accounts.json` в каталоге проекта. Пароли не находятся в Git и не показываются на слайдах. Аккаунты `dispatcher`, `subscriber`, `technician` предназначены соответственно для диспетчера, абонента и сотрудника ST-001. Для других сотрудников смотрите `staff_id` и соответствующий `username` в этом файле. Ранее созданные вручную аккаунты сохраняют свои пароли.

Для одновременной работы ролей используйте разные профили браузера или обычное окно и инкогнито. Вкладки одного профиля разделяют сессию. При последовательной проверке нажимайте «Выйти» перед входом другой роли.

Мобильная версия использует тот же адрес и аккаунты. На телефоне `127.0.0.1` означает сам телефон: текущая Docker-конфигурация доступна только на компьютере. Для подключения физического телефона нужен отдельно настроенный сетевой адрес приложения; для защиты на компьютере можно использовать режим телефона в браузере. Адаптивная вёрстка не требует отдельного приложения.

2. Выбрать «Копия набора на другую дату».
3. Выбрать исходную смену, например 16 ноября, и свободную новую дату.

Используются загруженные справочники и матрица. После создания также постройте первоначальный план. Копия набора всегда создаётся в деморежиме.

### Время смены: демонстрационный и рабочий режимы

Под заголовком каждой рабочей страницы находится панель часов: режим, подтверждённое время и статус. Часы общие для всех участников выбранной смены и хранятся на сервере; выбор другой даты или выход из кабинета их не сбрасывают. Исполнитель может прочитать описание режима, менять часы и режим может только диспетчер. В списке дат есть отметки «демо» / «рабочий».

**Для защиты — демонстрационный режим.** Откройте «Время и режим». Часы стоят, пока диспетчер не изменит их:

1. «+5 мин», «+15 мин», «+60 мин» продвигают время и обновляют план.
2. «К следующему визиту» выбирает самое раннее будущее начало визита среди маршрутов выбранной смены. Кнопка ведёт к ближайшему визиту всей команды.
3. «Установить время смены → Применить время» задаёт точный момент внутри того же дня. Перевод назад запрещён.
4. После шага обновляются расписание, риски и версия; TIME_TICK виден в ленте. Часы сами по себе не подтверждают фактическое выполнение. Исполнитель по-прежнему нажимает «Начал работу» и «Закончил работу».

Для шагов нужен построенный план. Если требуется начать демонстрацию заново, создайте копию на свободную дату: история исходной смены сохраняется. На 23 ноября подготовлена отдельная копия для проверки этих кнопок. Основную смену 16 ноября можно оставить на 08:45.

**Для работы сегодня — рабочий режим.** В «Центре управления → Новая смена» выберите пустую смену и «Рабочий — текущее время Екатеринбурга». Форма подставит сегодняшнюю дату. Создание не заменяет существующий день. Нажмите «Построить план», затем принимайте обращения обычным способом.

Сервер проверяет рабочие часы каждые 15 секунд и продвигает смену по минутам, даже при закрытом браузере. Go API и PostgreSQL в Docker должны работать. «Синхронизировать сейчас» обновляет время до текущей секунды. При подтверждении начала/завершения работ и при событиях рабочее время определяется сервером до секунды; введённая пользователем дата события не переводит рабочие часы.

Существующую демонстрационную смену можно перевести в рабочую только сегодня и только если её время не опережает сервер. Включение подхватывает текущий момент и пересчитывает план с сохранением истории. Для будущей даты, например 16 ноября во время проверки 15 ноября, кнопка заблокирована с объяснением. Рабочий режим не служит ускоренной демонстрацией.

«Перейти в деморежим» синхронизирует и останавливает часы. Возврат в рабочий режим догоняет сервер, сохраняя историю переключений (автор и время). Нельзя откатить часы назад ради восстановления старого состояния. Режим сохраняется после перезапуска API; рабочие часы догоняют сервер при его запуске.

После полуночи Екатеринбурга рабочий день завершается на 23:59:59 своей даты; автоматически другая дата не создаётся. Для нового дня создайте отдельную рабочую смену. Для действий с исторической сменой переключите её в деморежим. При ошибке или отставании синхронизации показывается предупреждение и остаётся последнее подтверждённое время; не считайте его актуальным, пока ошибка не устранена.

Для подготовки из терминала доступна повторяемая команда:

```powershell
npm run demo:prepare -- --date 2026-11-16 --source 2026-10-28 --accounts
```

Она создаёт отсутствующую датированную копию, строит отсутствующий план и создаёт недостающие демонстрационные аккаунты исполнителей. Уже существующие смены и пароли сохраняются. Отчёт — `work/demo-preparation.json`; пароли — `work/demo-accounts.json`. Для другой защиты замените дату. Создание массовых демо-доступов рассчитано на текущий синтетический набор.

## 4. Диспетчерская: работа с 400 нарядами

1. Выберите 16 ноября и проверьте число нарядов в сводке.
2. Для первого расчёта нажмите «Построить план» и дождитесь результата. После событий или ручного назначения первоначальная сборка блокируется; используйте события и назначение из карточки.
3. Используйте поиск по номеру, адресу или названию работы. Фильтры «Все», «Без назначения», «В работе», «ПГП», «Завершены» меняют список.
4. Выбор сотрудника в блоке команды фильтрует его наряды и показывает дорожный маршрут. Чтобы вернуться к остальным заявкам, снимите выбор сотрудника и включите «Все».
5. Нажатие карточки открывает исполнителя, окно, фактическое плановое начало/окончание, технологию, оборудование и причину неназначения, если она есть.
6. Гант показывает порядок работ, перерывы и пополнения. Плановый блок не является подтверждением фактического выполнения.
7. Предупреждения показывают активные риски, неназначенные наряды и групповые повреждения. «Вся история» раскрывает предыдущие предупреждения.

При подключённом PyVRP первоначальный план может улучшить исходный Go-вариант. Предложения проходят проверку Go; при отсутствии допустимого улучшения сохраняется baseline. Число назначений зависит от набора и условий конкретного запуска. На защите показывайте фактическую сводку, а не обещайте заранее одинаковое число.

### Новая заявка непосредственно от диспетчера

«Диспетчерская → Новая заявка» создаёт сразу выездной наряд:

1. Выберите адрес и узел подключения, затем подходящий вид работ. Частный сектор нельзя выбрать для МКД; технологии установки должны соответствовать адресу.
2. Проверьте время регистрации, окно визита, контрольный срок, оборудование и допуск к высоте. Даты должны принадлежать выбранной модельной смене по правилам формы.
3. Нажмите «Создать и распределить».
4. После сохранения открывается карточка нового наряда. В ней виден назначенный сотрудник или причина отсутствия назначения. Поиск фокусируется на новом номере; для возврата к полному списку очистите поиск.

Первое назначение выполняет алгоритм. Из карточки можно выбрать другого допустимого специалиста или назначить ещё не распределённый наряд. Такой наряд не появляется во «Входящих обращениях абонентов»: этот список относится к обращениям из клиентского кабинета.

### Ручное назначение и переназначение

1. Войдите как диспетчер, выберите смену и откройте карточку наряда. Для начала нужен построенный план.
2. Нажмите «Назначить специалиста» либо «Переназначить специалиста».
3. Выберите нового исполнителя. Список включает сотрудников справочника; недопустимые варианты отключены. Разверните «Недоступные варианты и причины», чтобы увидеть пояснения. Проверяются профиль, технология, допуск к высоте, отсутствие, недоступность, оборудование и возможность вставки в расписание с дорогой, сменой, обедом и пополнением.
4. Проверьте блок «После подтверждения»: новое плановое время, изменение общего времени переездов и все затронутые наряды с прежними и новыми интервалами. Система пересчитывает остатки двух маршрутов; остальные назначения сохраняют исполнителей. Другие визиты на этих маршрутах могут сдвинуться в пределах ограничений.
5. Введите причину от 3 до 2000 символов и нажмите «Подтвердить назначение».
6. Проверьте исполнителя и время в карточке, маршрут на карте и Гант. В «Ленте смены → Ручные назначения» сохраняются автор, причина, прежний/новый сотрудник, модельное время и версия плана.
7. У прежнего исполнителя наряд исчезает, у нового появляется в его смене. Если наряд связан с клиентским обращением, абонент увидит актуальные имя специалиста и плановое время при обновлении данных. Начало/завершение по-прежнему подтверждает назначенный исполнитель.

Начавшийся по модельному расписанию визит, работа с фактом начала/завершения, отменённый наряд, переданный визит и обращения ПГП не переназначаются. Если план изменился во время выбора, нажмите «Обновить проверку» и заново оцените последствия. Повторная отправка того же подтверждения не создаёт дубль.

Пустой список допустимых вариантов означает, что вставка с сохранением остальных заданий не найдена. Это особенно вероятно на плотном наборе из 400 нарядов. Назначение не обходит ограничения и не гарантирует распределение всех заказов; оно не выполняет глобальную перестановку всех маршрутов. Ручной выбор не закрепляет сотрудника навсегда: последующие события могут изменить его при конфликте. Перетаскивание визитов на Ганте пока не поддерживается.

Для повторяемого показа выберите 21 ноября, откройте ORD-20261121-0001 и назначьте другого доступного сотрудника. Модельное время 08:30, поэтому визит ещё можно менять. Основной набор для показа масштаба остаётся на 16 ноября.

| Событие                  | Какие данные нужны                                            | Результат                                             |
| ------------------------ | ------------------------------------------------------------- | ----------------------------------------------------- |
| Обновление времени       | Новое модельное время того же дня, не раньше текущего         | Обновление состояния смены, рисков и версии плана     |
| Отмена заявки            | Номер наряда, время, причина                                  | Отмена ещё не начатого выезда по правилам сервера     |
| Недоступность мастера    | Сотрудник, начало, причина, при временной — конец             | Перепланирование доступного остатка маршрутов         |
| Задержка визита          | Сотрудник и начавшийся визит, новое ожидаемое окончание       | Продление визита и перепланирование последующих работ |
| Передача в подразделение | Начавшийся визит, время фактического окончания, подразделение | Фиксация передачи по правилам кейса                   |
| Новая заявка             | Заполняется отдельной кнопкой «Новая заявка»                  | Добавление наряда и событийное распределение          |

После успешного события версия плана увеличивается, запись появляется в журнале. Если событие противоречит ограничениям, интерфейс показывает ошибку; оно не должно частично изменять сохранённые данные. Для примера недоступности на копии учебного дня удобно выбрать раннюю смену до первого визита и ограниченный интервал, например 08:45–11:00. Бессрочная недоступность после начала визита до обязательного обеда может оказаться несовместима с ограничениями и быть отклонена.

### Карточки сотрудников и проверка влияния на план

Откройте **«Центр управления → Команда»** под аккаунтом диспетчера и выберите нужную дату. Поиск работает по имени, коду, специализации и технологии. В каждой карточке показаны участие в смене, число визитов, технологии, допуск, время и начальный запас оборудования.

1. Нажмите «Открыть карточку» у сотрудника.
2. Измените имя, специализации, технологии, высотный допуск, начало/конец смены, окно начала и длительность обеда, начальный запас ONT/ROUTER/STB и вместимость после пополнения. Для полного отсутствия отметьте «Отсутствует в выбранной смене».
3. Нажмите «Предпросмотр изменений». На этом шаге данные ещё не сохраняются.
4. Проверьте изменённые поля, количество визитов и неназначенных нарядов, разницу переездов и полный список затронутых нарядов. Для каждого показаны прежний/новый сотрудник и интервал. Если наряд потеряет исполнителя, показана причина. При строгих ограничениях система может оставить часть работ без назначения.
5. Введите причину от 3 до 2000 символов и нажмите «Подтвердить изменения». Настройки, новый план и история сохраняются вместе; версия плана увеличивается. Переход в другую дату не сбрасывает сохранённые настройки.
6. Откройте ту же карточку повторно: раздел «История карточки» содержит автора, причину, модельное время, прежние/новые значения и число затронутых нарядов. В диспетчерской запись видна в «Ленте смены → Изменения сотрудников».
7. Проверьте обновлённые назначения и маршруты. Последующие события, ручное назначение, кабинет исполнителя и сведения для абонента используют сохранённые настройки.

**Область действия — выбранная смена.** Другие даты и исходный шаблон справочника не меняются. Чтобы перенести настроенную команду на новую дату, создайте копию этой смены. Новая пустая смена использует исходный справочник. Код сотрудника, привязка к СЦ, стаж и учётная запись в этом редакторе не изменяются; доступы управляются в разделе «Доступы».

Карточку можно подготовить и до первого расчёта. Предпросмотр сообщит, что плана ещё нет; сохраните настройки, затем нажмите «Построить план» в диспетчерской. Если план уже есть, сохранение карточки перепланирует его остаток.

После начала любого пункта маршрута сотрудника по модельному времени, включая выезд из СЦ, либо при наличии фактов выполнения настройки этой смены фиксируются. Редактор объяснит блокировку. Для недоступности в течение дня используйте отдельное событие «Недоступность мастера»; оно предназначено для изменения остатка смены. Если смена изменилась во время редактирования, закройте карточку, обновите данные и откройте её снова — старые значения не должны перекрывать чужое изменение.

Для демонстрации используйте **22 ноября, ST-001**. В сохранённом примере сотрудник отсутствует: до подтверждения показаны 7 теряющих назначение нарядов; после — 39 сотрудников на смене и сохранённая история. Можно снять отсутствие, посмотреть новый прогноз и подтвердить возвращение. Основной день 16 ноября остаётся без изменений. Отдельный проверочный запрос предпросмотра занял около 0,58 с на 40/400; это одиночный замер, не нагрузочный норматив.

## 5. Полный цикл клиент → диспетчер → исполнитель

Для живого показа удобна отдельная пустая смена, чтобы свободные ресурсы не зависели от загрузки 400 нарядов. На 17 ноября уже сохранён выполненный пример; для нового прохождения создайте свободную дату, например 19 ноября. Во всех шагах указывайте именно созданную дату.

### Абонент

1. Войти как `subscriber`.
2. «Мои обращения → Заказать услугу».
3. Для первого примера выбрать «Проверка и ремонт», адрес «Екатеринбург, учебный адрес №001 (синтетический)», телефон, дату подготовленной смены и описание.
4. Нажать «Отправить обращение». Сохранить номер REQ-…; появится подтверждение приёма.

Желаемая дата пока не является согласованным окном выезда. Повтор отправки неизменённой формы при сбое защищён от создания дубликата.

### Диспетчер

1. Открыть «Обращения абонентов», выбрать подготовленную смену, нажать «Обновить обращения».
2. Найти REQ-… и при необходимости нажать «Взять на рассмотрение».
3. Нажать «Одобрить и распределить».
4. Сопоставить адрес со справочником. Выбрать «Устранение неисправности», окно 14:00–16:00 и нужное оборудование; для первого теста оставить нули. Ввести комментарий, подтвердить согласование окна.
5. Подтвердить одобрение. В карточке появится ORD-…, дата, назначенный специалист, плановое начало и его логин.
6. Если назначения нет, прочитать причину. Одобрение обращения само по себе не гарантирует свободного подходящего исполнителя.
7. Если у сотрудника нет аккаунта, «Центр управления → Доступы → Добавить аккаунт»: роль «Исполнитель», нужный ST-xxx, логин и первоначальный пароль от 12 символов. Для демо-набора недостающие аккаунты можно подготовить командой выше.
8. Если время визита ещё не наступило, нажать «К началу визита» и подтвердить «Перевести смену к визиту». Это продвигает время всей смены и может изменить риски других нарядов.

Для отклонения используется «Отклонить с объяснением». «Решить без выезда» означает, что вопрос решён без создания выездного наряда: эта кнопка не отправляет мастера. Одобренный выезд завершается через исполнителя.

### Исполнитель

1. Войти под аккаунтом назначенного сотрудника и выбрать ту же дату.
2. В «Следующем задании» посмотреть адрес, время и оборудование.
3. Нажать «Карта и адрес» или «Показать точку на карте». Карта приблизит адрес; номера обозначают порядок визитов. Светлым цветом выделяется дорожный участок к выбранной точке.
4. «Путь к заданию» показывает расстояние и оценку поездки от предыдущей плановой остановки. Это не GPS-навигация от текущего положения.
5. Нажать «Начать / завершить» для перехода к «Моим заданиям».
6. По прибытии нажать «Начал работу». Появятся статус «На объекте», время и поле отчёта.
7. После работы заполнить «Результат работы» и нажать «Закончил работу». Сохранятся статус «Выполнена», время и отчёт. Без старта и отчёта завершить работу нельзя; второе задание нельзя начать, пока первое в работе.
8. Для остановок смены раскрыть «Все остановки смены». Для расписания — соответствующую ссылку.

Следующим считается незавершённое задание. Просроченное по плановому времени задание не исчезает автоматически; выполненное остаётся в истории. При сообщении о задержке или собственной недоступности сервер проверяет права исполнителя и принадлежность задания.

### Результат для абонента и диспетчера

Открыть обращение и нажать «Обновить обращения» либо дождаться автоматического обновления (до 15 секунд). Появятся «Работа начата» / «Работа выполнена», время и отчёт. В диспетчерской статус наряда обновляется через снимок смены (обычно до 10 секунд или по кнопке обновления).

Начало и завершение используют модельные часы. Если их не продвигать между действиями, отметки могут совпасть. Для разных времён диспетчер продвигает модельное время между действиями. Раннее фактическое завершение пока автоматически не сокращает замороженное расписание и не освобождает плановую длительность визита.

## 6. Мобильный интерфейс

На узком экране основные разделы расположены в нижней навигации с подписями. В верхней полосе показаны аккаунт и выход. Выбор дня находится под заголовком; полная дата и количество заявок видны без сокращения до нескольких символов.

Проверены рабочие экраны при ширинах 320, 390 и 768 пикселей; полный клиентский цикл пройден в браузере на мобильной ширине 390 пикселей. Это проверка адаптивной версии в браузере, а не отдельное испытание на физическом телефоне.

У исполнителя есть быстрые переходы «Карта и адрес», «Начать / завершить», «Расписание». Карта занимает отдельный блок по ширине экрана, остановки раскрываются по запросу. Основные кнопки и поля увеличены для касания. Команда представлена адаптивными карточками; редактор сотрудника проверен при ширине 320/390 px. Широкие таблицы остальных справочников и Гант прокручиваются внутри своего блока по горизонтали.

При работе с длинными формами прокручивайте сам диалог. Кнопка закрытия остаётся в его заголовке. При потере связи показывается предупреждение; последний успешно загруженный снимок не означает, что новые действия уже сохранены.

Формулировка для жюри: «Мы проверяем жёсткие ограничения и показываем причины неназначения. Массовый учебный набор демонстрирует планирование, а живая заявка — реальную связь кабинетов и подтверждение работы исполнителем».

Не заявляйте реализованными GPS-трекинг, живые пробки, перетаскивание визитов, редактирование адресов/СЦ/нормативов через интерфейс или production-развёртывание. Ручное назначение и карточки сотрудников выбранной смены реализованы с проверкой ограничений и предпросмотром. AI-помощник отменён командой и в MVP не входит. География, сотрудники и нормативы учебные.

## 8. Частые вопросы

**«Исчезли 400 заявок».** Проверьте дату. Пустая или персональная смена не заменяет большой набор. Снимите фильтр сотрудника, очистите поиск и нажмите «Все». Исполнитель видит только свои назначения.

**«Создал заявку, но её нет во входящих».** Новая заявка диспетчера — сразу ORD. Клиент создаёт REQ в кабинете абонента. После одобрения они связываются.

**«Нельзя начать работу».** Проверьте логин и staff_id, дату, наступление планового начала и отсутствие другого активного задания. Календарь компьютера не заменяет модельное время.

**«План не назначил всё».** Откройте причину неназначения: технология, профиль, оборудование, время, недоступность либо отсутствие допустимой вставки в пределах бюджета. Не меняйте данные ради красивого процента.

**«Не вижу дорогу/подложку».** Проверьте OSRM и интернет для тайлов OpenStreetMap. Адреса и расписание остаются доступны при недоступной подложке. GPS и пробки не предоставляются.

**«Не получается скопировать старую смену».** Выберите свободную дату и корректный исходный набор. Исторические вручную введённые несовместимые типы работ могут быть отклонены новой проверкой. Исходная смена при этом не изменяется.

**«Обновление кнопок не появилось».** После пересборки выполните Ctrl+F5. Если выбран не тот день, поменяйте его в списке; приложение запоминает выбор.

**«Как начать чистую репетицию».** Создать пустую смену либо копию на новой дате и построить план. Для этого не требуется удалять базу или выполнять `demo:load -- --replace`.
